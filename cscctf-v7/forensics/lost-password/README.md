# Lost Password

**Event:** CSCCTF v7 · **Category:** Forensics · **Difficulty:** Hard · **Author:** jaarabd

## Description

> I forgot the password to my zip file. Good thing I had a packet capture running on my workstation at the time. How hard can it be?

## Files

- [`capture_01.pcapng`](capture_01.pcapng)
- [`archive.7z`](archive.7z)

Solver scripts: [`mousesolver.py`](mousesolver.py), [`keyboard_solver.py`](keyboard_solver.py).

## Solution

Three stages: a mouse capture gives the archive password, the archive holds a keyboard capture, and the keyboard capture gives a URL with the flag.

### 1. Mouse capture: draw the password

`capture_01.pcapng` contains USB traffic, not network traffic. The device at address `1.3.1` is a Redragon gaming mouse (Holtek Semiconductor, vendor ID `0x04d9`).

Extract the HID reports from the mouse:

```bash
tshark -r capture_01.pcapng -Y 'usb.src == "1.3.1" && usbhid.data' \
       -T fields -e usbhid.data > mouse_hid.txt
```

Unlike a standard mouse, which sends 8-bit movement deltas, this gaming mouse sends 16-bit ones. Each report is laid out as:

| Bytes | Field |
| :-- | :-- |
| 0 | Button bitmask (bit 0 = left click) |
| 2-3 | X delta, signed 16-bit little endian |
| 4-5 | Y delta, signed 16-bit little endian |

Most public USB mouse solvers assume 8-bit deltas and produce noise on this capture, so the report format has to be read and the parser adapted.

[`mousesolver.py`](mousesolver.py) accumulates the deltas into a cursor position and draws a dot wherever the left button is held:

```python
buttons = b[0]
dx = struct.unpack("<h", b[2:4])[0]
dy = struct.unpack("<h", b[4:6])[0]
x += dx; y += dy
if buttons & 1:
    draw.ellipse((x-4, y-4, x+4, y+4), fill="black")
```

```bash
python3 mousesolver.py    # writes drawing.png
```

The drawing spells out the archive password: `redragon_2026_mouse`.

### 2. Open the archive

```bash
7z x -predragon_2026_mouse archive.7z
```

This extracts `capture_02.pcapng`.

### 3. Keyboard capture: recover the typed text

The second capture is a USB keyboard, also at device `1.3.1` (a different capture session). Keyboard HID reports are the standard 8 bytes: byte 0 holds the modifier keys and bytes 2 to 7 hold up to six pressed key codes.

[`keyboard_solver.py`](keyboard_solver.py) maps each newly pressed key code to its character, using the shifted table when Left or Right Shift (`0x02` or `0x20`) is held:

```bash
python3 keyboard_solver.py
```

The typed text contains a URL:

```
https://www.pinterest.com/radndomffffccc/
```

### 4. Assemble the flag

The Pinterest board has 3 pins, each holding one fragment of the flag. Put them in order:

```
CSCCTF{r3dr4g0n_5n1ff3d_4nd_5p1ll3d}
```

## Design notes

- **Non-standard HID format.** The difficulty comes from the 16-bit mouse reports. Players who run a copied solver get garbage and have to work out the real report layout, which is the actual forensics skill being tested.
- **Real hardware.** Both captures were recorded from physical devices (a Redragon gaming mouse and a USB keyboard) rather than generated by a script, so timing, idle reports and device enumeration look like a real capture.
- **Chained stages.** Mouse traffic unlocks the archive, the archive hides keyboard traffic, and the keyboard traffic leads off the capture to an OSINT style final step. Each stage uses a different skill, and none can be skipped.
- **Flag off the files.** The final fragments live on an external page, so the flag never appears in any handed out file and cannot be found by searching the captures or the archive.
